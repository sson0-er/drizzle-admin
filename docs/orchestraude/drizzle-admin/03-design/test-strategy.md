# Test strategy

All tests live in `test/` and run with `pnpm test` (vitest 5). Integration tests use `app.request()` / `admin.fetch()` and are parameterized over in-memory SQLite (better-sqlite3) and PGlite (`describe.each(dialects)`). HTML assertions check specific elements through the stable selectors in [interfaces/views.md](interfaces/views.md); there are no full-page snapshots.

- `db.ts`: `export const dialects: DialectFixture[]`, where `DialectFixture = { name: "sqlite" | "pglite"; dialect; setup(opts?: { logger? }): Promise<{ db; schema; close(); queryCount(): number }> }`. Each setup creates fresh tables from constant DDL (`test/fixtures/ddl-sqlite.sql.ts`, `ddl-pg.sql.ts`) that matches the drizzle schemas, then inserts the fixture rows. Query counting uses a Drizzle custom logger (`{ logQuery() { n++ } }`).
- `fixtures/schema-sqlite.ts`, `fixtures/schema-pg.ts`: logically equal tables with the same property keys. `authors` (id auto, name text notNull unique, email, active boolean, role enum, createdAt timestamp default), `articles` (id auto, title notNull, body long text, authorId FK → authors notNull, publishedAt timestamp nullable, meta json, views integer, score real, big bigint) and `kv` (text PK, value). `articles.big` is `bigint("big", { mode: "bigint" })` on PG and `blob("big", { mode: "bigint" })` on SQLite, because SQLite `integer()` has no bigint mode; the SQLite DDL declares it `big BLOB` (decision 026). The PG schema additionally covers `text` vs `varchar`, `uuid`, `date()`, `date({mode:"date"})` and identity for introspection. It also has a PG-only table `events` (id serial, `day` `date({mode:"date"})` notNull, `code` uuid defaultRandom notNull, `amount` numeric, `mood` pgEnum `mood` (`calm`, `busy`), `note` text, `due` `date()` nullable (string mode)), which is used by the PG-only cases below (`describe` runs for `pglite` only).
- `app.ts`: `makeAdmin(fixture, overrides)` returns `{ admin, client }`. `client` is a cookie-jar wrapper around `admin.fetch` that sends `Origin: http://localhost` on POST, plus `login()`, `get(path)`, `post(path, form, { withToken = true })` and `csrf()` (reads the token from the last page's `_csrf` input).
- `html.ts`: parse5-based `parse(html)`, `qsa(root, { tag, id?, cls?, attrs? })`, `qs`, `text(node)`, `attr(node, name)`.

SQLite blob-bigint rule (decision 026): on SQLite, `articles.big` values compare as BLOBs, so 10 sorts before 9 and range comparisons are bytewise (evidence: 2026-10-07-sqlite-blob-bigint-ordering). Tests that run on SQLite (repository, list, query, routes) must not assert numeric ordering or range filtering on `big`; sort and paging assertions use other columns, or the test is PG-only. ## Integration coverage (§12)
Changed 2026-10-07: hook ctx assertions use the fixed `HookCtx` (decision 015). Review revision: date-only round trip, fallback route, error page and logging cases (decisions 019, 022).
Changed 2026-10-08: `basePath: "/"` trailing-slash cases (decision 029) and flash display on the page after a redirect (decision 027).
Changed 2026-10-08: trailing-slash cases for the allowlist rule (tab, LF, CR, `///` paths, ordinary redirect with a query) after the tab bypass of the denylist (decision 029).
Changed 2026-10-08: whitespace case `/a%20b` → 404; LF/CR cases are a known limitation (decision 029).

- Every page GET returns 200: dashboard, list, add, change, delete, login, action confirmation; static CSS 200 with long cache.
- Trailing slash: `/admin`, `/admin/authors`, `/admin/authors/1/change` → 301 to the slashed URL with the query kept; unknown model/pk → 404.
- Trailing slash, open-redirect guard (decision 029, `admin.fetch`). Each "→ 404 without `Location`" case asserts status 404 and `res.headers.get("Location") === null`.
  - `basePath: "/"`:
    - `GET //evil.example`, `GET /%5Cevil.example`, `GET ///evil.example`, `GET /%09/evil.example` → 404 HTML page (layout, `Content-Type: text/html`) without `Location`.
    - `GET /%0a/evil.example`, `GET /%0d/evil.example` → 404 without `Location`. Assert only status and the missing `Location`: these paths do not reach any admin route (Hono's `/*` does not match a decoded LF/CR), so the body is Hono's plain `404 Not Found` (evidence: 2026-10-08-trailing-slash-control-char-bypass; accepted known limitation, decision 029). Do not assert the security headers on these two responses.
    - `GET /a%20b` → 404 HTML page without `Location` (whitespace is outside the allowlist).
    - `GET /users?a=1` → 301 with `Location: /users/?a=1` (`users` is not a fixture model; the redirect does not depend on registration); `GET /authors?x=1` → 301 with `Location: /authors/?x=1`.
    - `GET /` (logged in) → dashboard 200.
  - `basePath: "/admin"`: the same paths under the prefix: `GET /admin//evil.example`, `GET /admin/%5Cevil.example`, `GET /admin///evil.example`, `GET /admin/%09/evil.example` → 404 HTML page without `Location`; `GET /admin/%0a/evil.example`, `GET /admin/%0d/evil.example` → 404 without `Location`; `GET /admin/a%20b` → 404 HTML page without `Location`; `GET /admin/users?a=1` → 301 `Location: /admin/users/?a=1`; `GET /admin?a=1` → 301 `Location: /admin/?a=1`.
  - For every 301/302/303 asserted anywhere in the route tests the `Location` starts with `${prefix}/`, does not start with `//`, and contains no `\`, no control character (U+0000-U+001F, U+007F) and no whitespace (the external `loginUrl` redirect excepted).
- Flash display (decision 027): after a redirect that sets a flash (e.g. a successful add), the next GET page shows the message once (`ul.messagelist`) and a second GET does not.
- List: search (incl. wildcard literal), each filter kind with selected state and other params preserved, header cycle asc → desc → off, non-listDisplay `o` ignored, pagination and total, ✓/✗, `-` for null, FK link + label, truncation. No N+1: query count for a page with 30 rows of `articles` (FK displayed) equals that for 3 rows.
- Add/change, for every column type: happy path (303 + flash + DB state), each coercion error (400, values kept, `ul.errorlist`), required, unique violation (form error, 400), `validate` errors, `beforeSave`/`afterSave` called with the expected `HookCtx` (`mode` add/change, `user`, `db` identical to `AdminConfig.db`; decision 015), three buttons → correct Location, mass-assignment ignored, readonly/auto PK not writable.
- Date-only (PG only, `events`): for `timeZone` `Asia/Tokyo` and `America/New_York`, add with `day=2026-10-07` → `select day::text` returns `2026-10-07`; the change page input value is `2026-10-07`; the list cell shows `2026/10/07`; change POST keeps the day (decision 019).
- Date-only strings (PG only, `events.due`, decision 023): for `timeZone` `Asia/Tokyo` and `America/New_York`, the add page renders `input[type=date][name=due]`; add with `due=2026-10-07` → 303 and `select due::text` returns `2026-10-07`; the change page input is `type=date` with value `2026-10-07`; the list cell shows `2026-10-07`; change POST keeps the value; `due=2026/10/07` → 400 with `messages.invalidDate` on the field and the raw value kept. With `listFilter: ["due"]`, the filter sidebar offers the date presets and `f_due=today` lists only the row whose `due` is today's calendar date in `timeZone` (the test inserts rows for that date and the day before, both computed with `toDateOnly(calendarPresetRange("today", new Date(), tz).start)` and its previous day; the precise `now` boundary is covered by the repository test with injected `now`).
- Search on PG `events` with `searchFields` code/amount/mood → 200 with matching rows (decision 018).
- Fallback and errors (decision 022): with the admin mounted under an outer `new Hono()` at `/admin`, a logged-in POST with a valid token to `/admin/nope/x/y/` → 404 HTML page (`h1`, layout), and a logged-in `PUT /admin/authors/` (no body) → 404 HTML page, not the outer app's plain 404. The Origin-check 403 is an HTML page containing `messages.csrfFailed`. With `console.error` spied: a throwing `formatters` function → 500 and the log contains its message; a forced DB error (`kv` registered with `searchFields: ["value"]`; drop the `kv` table, then GET its list with `q=secretvalue`) → 500 and the log does not contain `secretvalue`.
- Delete: confirm page, success, FK constraint failure → error flash and redirect to the list; bulk delete confirm + execute; `beforeDelete` called per row with `mode: "delete"`.
- Actions: no selection warning, custom action with and without confirm, returned message flashed, unknown action.

## Phase gates
Changed 2026-10-07: the phase-1 smoke content is defined (example row above).

At the end of every phase, `pnpm test`, `pnpm typecheck`, `pnpm lint` and `pnpm build` all pass. Phase 1 runs the phase-1 part of the example smoke test, which loads the example modules (Hono, better-sqlite3, the library) under vitest. Phase 1 also starts `pnpm example` (tsx + @hono/node-server), checks that `GET /` answers with 302, and stops it. The implementer reports this check as run or not run; it is not part of `pnpm test`. Before phase 5, the routes run without the auth guard. The phase-5 tests then switch the shared `makeAdmin` helper to logging in by default.
Manual acceptance (after all tasks): the user runs `pnpm example` and checks login, dashboard, list, add, change, delete and actions in a browser (interfaces/example.md).
