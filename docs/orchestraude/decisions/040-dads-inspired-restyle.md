# 040: Restyle the admin after DADS values, with our own CSS, markup and dark palette

- Date: 2026-10-08
- Status: accepted (post-v1 enhancement, user request)

## Context
After v1 the user asked for a look and feel closer to the Japanese Digital Agency design system (DADS), without adopting DADS wholesale. The user fixed these constraints. Keep our markup, selectors, test hooks, the single embedded stylesheet `src/static/admin-css.ts`, the decision 039 icons, no JavaScript, no external fonts or CDNs (system font stack), and the responsive layout under 768px. Body text and forms follow DADS density (16px, line-height about 1.7, letter-spacing 0.02em, about 8px control radius, solid/outline/text buttons, 12px-radius notifications with a semantic border). The changelist table stays denser (about 14px, tighter padding). Dark mode is our own palette derived from DADS hues, with verified contrast (text at least 4.5:1, non-text at least 3:1) and a dark variant of the black and yellow focus ring. The CSS is our own, inspired by DADS values; nothing is copied verbatim, and nothing suggests the work is by the Digital Agency. Delete actions need our own danger style. All of this fits in one implementation task.

## Decision
Changed 2026-10-08: user answer to Q11 applied: option (a), no required marker in this restyle (point 10); it may become a separate small task later.
1. **Approach.** Rewrite the rules inside `ADMIN_CSS` only. The full specification is views-style.md: 28 color tokens, typography, reference rules, focus ring and the 767px block. No view, widget or message file changes. Existing classes, ids, `name` and `data-*` hooks stay. Button variants are chosen through existing selectors. `ADMIN_CSS_VERSION` changes by itself.
2. **Tokens.** All custom properties are lowercase `#rrggbb` colors, and both schemes define the same names. Light values are DADS primitives from `@digital-go-jp/design-tokens` 2.0.1: blue-900 primary, blue-1000 links, gray-800 text, gray-420 dividers, gray-600 input borders, green-800 / yellow-900 / red-900 semantics. The v1 Django palette tokens are removed. `--icon-success`, `--icon-warning` and `--error-fg` keep their names (decision 039) with new values.
3. **Dark palette (our own).** Neutral gray-900 page and gray-50 text. Light tints of the same hues for interactive and semantic colors: blue-300 / 200 / 100, red-400 / 300 / 200, green-300, yellow-400. The darkest steps (blue-1100, red-1200) serve as hover tints. One non-DADS neutral is used, `#262626`, for zebra and title bars.
4. **Focus ring.** On every `:focus-visible`: a 4px outline, a 2px offset and a 2px `box-shadow` halo. Light uses a black outline with a yellow-300 halo, as in DADS. Dark swaps them (yellow-300 outline, black halo). Links and the header logout button also fill yellow-300 with black text. This rule is placed last with specificity (1,1,1), so it overrides every link color rule.
5. **Density.** Body 16px / 1.7 / 0.02em. Form controls and buttons are 48px high with an 8px radius. The changelist toolbar uses 40px controls. Tables (and filter, paginator, breadcrumbs) use 14px / 1.5 text with 8px/12px cell padding.
6. **Buttons.** Solid: the default `button`, plus the list "add" link. Outline: search, run, "save and add another", "save and continue". Text: the header logout button and the cancel links. Danger solid (our own): the final delete submits (`#delete-form`, `form.delete-action`). Danger outline (our own): `a.deletelink`.
7. **Header, breadcrumbs, pagination (our own; DADS has none to copy).** A white header with a bottom divider, a 20px bold site title and 14px user tools. Plain 14px breadcrumbs. Page numbers are 36px boxes with a 6px radius, and the current page is solid primary.
8. **Flash and error note.** A white card with a 3px semantic border, a 12px radius and a 24px leading icon. The text is the body color. `.errornote` uses the same card in red.
9. **Fonts.** `"Noto Sans JP", "Noto Sans CJK JP", "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Yu Gothic", Meiryo, system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`. These are local names only: no `@font-face` and nothing downloaded.
10. **Not adopted.** No visited or active link colors, no "※必須" required marker (user answer to Q11, option (a); possibly a separate small task later), no DADS class names, components or JS, no elevation shadows, no `@media (hover: hover)` guard.
11. **Attribution.** A TypeScript comment above `ADMIN_CSS` (not served) states that the values are inspired by the DADS tokens 2.0.1 (MIT), that the work is our own, and that it is not made or endorsed by the Digital Agency. There is no README mention.

## Alternatives considered
- **Adopt DADS snippets / class names (wholesale):** excluded by the user. It would also change markup and test hooks, require the MIT notice for pasted code, and track a beta that is tagged often (evidence: 2026-10-08-dads-html-snippets-repo, 2026-10-08-dads-license-notices).
- **Depend on `@digital-go-jp/design-tokens` and read its CSS variables:** gives exact token names, but adds a runtime dependency for about 30 values. It would need the package's CSS bundled into our string or served as a second file, which conflicts with the single embedded stylesheet. It is also light-only, so dark mode stays our own anyway (evidence: 2026-10-08-dads-design-tokens-package). Rejected.
- **Keep the black+yellow ring unchanged in dark mode:** a black outline on `#1a1a1a` is nearly invisible (1.21:1; evidence: 2026-10-08-dads-restyle-palette-contrast; not checked in a browser). Rejected. **A single yellow outline without a halo:** visible, but the outline merges with a yellow-filled link in dark mode. The black halo separates them (14.74:1). Rejected.
- **CSS `light-dark()` for the dark palette instead of a second `:root` block:** one declaration per token. Rejected because the existing tests and decision 039 rely on the two-block structure, and browser support was not checked (unverified).
- **Blue (blue-900) header band, as in v1:** keeps the strong identity, but DADS pages are flat and white with strong borders. The yellow focus fill on the site title would also need a separate rule. Rejected for the white header.
- **DADS dense table values (12px/16px padding, 16px text):** closer to DADS, but shows fewer rows per screen, against the user's density choice. Rejected.
- **Solid red for every delete control:** simpler, but it gives the same weight to the link that only opens the confirmation page and to the irreversible submit. Rejected in favor of outline for the link and solid for the final submit.
- **Yellow focus fill only on text-type controls (as DADS):** needs exclusions for the button-styled links (`:not()` lists or extra rules). Rejected for one rule covering all links.
- **README credit line:** not required for edited use (evidence: 2026-10-08-dads-license-notices). A credit in user-facing docs could also be read as association with the Digital Agency. Rejected; the source comment documents the value snapshot for maintainers.
- **Error red-800 (`#ec0000`) as in DADS:** 4.6:1 on white but 4.11:1 on the zebra gray, below 4.5:1. Red-900 keeps 5.18:1 (evidence: 2026-10-08-dads-restyle-palette-contrast). Rejected.

## Rationale
- The values come from the DADS token package and its snippets: blue-900 primary, 16px/1.7/0.02em body, 8px control radius, 12px notification radius with a 3px border, the black outline / yellow halo focus ring, and solid/outline/text buttons (evidence: 2026-10-08-dads-design-tokens-package, 2026-10-08-dads-html-snippets-repo, 2026-10-08-dads-a11y-focus-contrast). Using values instead of pasted code means no DADS code is copied. Edited, snippet-derived UI needs no attribution, but must not look as if it were made by the Digital Agency (evidence: 2026-10-08-dads-license-notices). Whether bare values are protected is a legal question we did not answer (unverified).
- DADS defines no dark tokens and no `prefers-color-scheme` rules (evidence: 2026-10-08-dads-design-tokens-package), so the dark palette is ours. Every text pair is at least 4.5:1 and every non-text pair (icons, input borders, flash borders, focus ring) at least 3:1 in both schemes. Examples: dark link 8.76:1, dark danger fill text 6.51:1, dark focus outline 12.21:1 (evidence: 2026-10-08-dads-restyle-palette-contrast). Decorative dividers (gray-420 in light) are not required to reach 3:1.
- DADS has no danger button, site header, sidebar or numbered pagination (evidence: 2026-10-08-dads-html-snippets-repo). Those parts reuse DADS shapes (8px radius, 3px semantic border) with our own colors.
- Only the stylesheet changes, so the risk is visual. No route, view or test hook changes, and the restyle fits in one task.
- System font stack: §11 forbids external fonts, and DADS's own stack loads Noto Sans JP from Google Fonts (evidence: 2026-10-08-dads-html-snippets-repo). Glyph metrics of the fallback faces at line-height 1.7 are unverified.

## Consequences
- Changed: `src/static/admin-css.ts` only (the `ADMIN_CSS` string and the comment above it). New test file `test/admin-css.test.ts`. The existing CSS tests in `test/views.test.ts` pass unchanged.
- Visual changes users notice: white header, underlined links, larger text and controls on forms, red outline delete link, yellow and black focus ring, card-style flash messages, error flash text no longer red, page numbers as boxes.
- The decision 039 icon colors are superseded (point 6 of 039): `--icon-success` light `#197a4b` / dark `#71c598`, `--icon-warning` light `#927200` / dark `#ffc700`. The 039 icon rules and markup are unchanged.
- The values are a snapshot of DADS tokens 2.0.1 (beta site v2.18.0). Later DADS changes are not tracked.
- Browser rendering (fonts, forced-colors, the halo inside the offset) is not verified by tests. The user's manual browser check covers it.
- Docs: views-style.md (new), views.md, test-strategy.md, README.md (components and index), decisions-and-evidence.md, questions.md (Q11, resolved: option (a)). project-setup.md is unchanged: the README outline has no styling section and gets no credit line.
