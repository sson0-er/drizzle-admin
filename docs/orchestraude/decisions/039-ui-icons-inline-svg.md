# 039: UI icons as static inline SVG from a fixed internal set

- Date: 2026-10-08
- Status: accepted (post-v1 enhancement, user request)

## Context
After v1 the user asked for icons to make pages easier to scan. Scope chosen by the user: buttons and links (add, change, delete, save, search, logout and similar), flash messages per level, boolean list cells (colored icons instead of plain `✓` / `✗`) and the dashboard model list. Constraints (§11, §1): no external fonts or CDNs; core features work without JavaScript; server-rendered Hono JSX only; all UI text in `src/messages.ts`; works in light and dark mode (`prefers-color-scheme`) and at narrow widths. Further requirements from the request: icons are static constants, never built from user data (XSS); decorative icons are `aria-hidden`; boolean cells keep an accessible text equivalent; small CSS; `currentColor` theming; no change to existing selectors or test hooks.

## Decision
Changed 2026-10-08: point 6 colors superseded by decision 040 (DADS-inspired restyle); the icon markup and rules are unchanged.
Changed 2026-10-08: user answers to Q8-Q10 applied: point 5 extended to read-only boolean form fields (Q9, changed from the first default); Q8 and Q10 confirmed as designed.

1. **Mechanism: inline SVG.** A new module `src/views/icons.tsx` exports an `Icon({ name })` JSX component that renders one `<svg>` with one `<path>` from a frozen internal table `ICON_PATHS: Readonly<Record<IconName, string>>`. `IconName` is a closed string union. Icons are not part of the public API (not exported from `src/index.ts`) and cannot be configured.
2. **Fixed icon set (9 icons, 16×16 grid, stroke-only, `stroke="currentColor"`):** `plus`, `pencil`, `trash`, `check`, `x`, `search`, `logout`, `triangle-alert`, `circle-alert`. Path data and placement: views.md "Icons".
3. **Placement:** dashboard rows (`a.addlink` plus, `a.changelink` pencil); list (`a.addlink` plus, search submit `search`); form (`_save` check, `_addanother` plus, `_continue` pencil, `a.deletelink` trash); delete page (submit trash, cancel x); action confirmation (submit trash for the built-in delete, check otherwise; cancel x); header logout button (`logout`); flash `li` per level (`success` → check, `warning` → triangle-alert, `error` → circle-alert; the three existing levels only, no `info` level, Q8); boolean list cells and read-only boolean form fields (true → check, false → x). Every icon sits before its visible text. No control becomes icon-only. The action `run` button, the login button, paginator, filter, breadcrumb and cell links stay text-only; the dashboard gets icons on each model row's add and change links, with no per-model icon (Q10).
4. **Accessibility:** every `<svg>` carries `aria-hidden="true"` as a literal attribute, and icons never contain text nodes, so the text of links, buttons and flash items is unchanged. A boolean list cell renders `<span class="boolean-mark" data-bool="true|false">` with the icon plus `<span class="visually-hidden">` holding `messages.yes` / `messages.no` (existing keys). Screen readers and the parsed text get "はい" / "いいえ" instead of the glyphs `✓` / `✗`. The same markup is used for read-only boolean form fields (point 5).
5. **Boolean detection:** `format.ts` gains `cellBoolean(args)`, which returns the boolean exactly when rule 4 of `formatCell` is the first matching rule (not masked, no formatter, non-null, no `fkLabel`, `typeof value === "boolean"`), else `undefined`. The list route puts it into the new optional `Cell.bool`. `formatCell` and `formatValue` are unchanged. Read-only boolean form fields (user answer to Q9): `DisplayValue` (`src/forms/widgets.tsx`) renders `<BooleanMark value={value} />` inside its `span.readonly` when `typeof value === "boolean"` and the widget is not `password` (the mask still wins). `widgets.tsx` already imports `views/format.ts`, and `views/icons.tsx` imports only `messages` and a type, so this adds no module cycle and no new dependency direction. As a result, `✓` / `✗` text is no longer rendered anywhere, though `formatValue` still returns it.
6. **Colors:** icons inherit `currentColor` (button, link, header and flash text colors) except two semantic colors: new custom properties `--icon-success` (light `#2e7d32`, dark `#81c784`) and `--icon-warning` (light `#8a6d00`, dark `#f5dd5d`), defined in both `:root` blocks. The error color reuses `--error-fg`. Boolean true uses `--icon-success`, false uses `--error-fg`; flash icons use the color of their level.
7. **Selectors:** no existing class, id, `name` or `data-*` attribute changes. New hooks: `svg.icon[data-icon=<name>]`, `span.boolean-mark[data-bool]`, `span.visually-hidden`.

## Alternatives considered
- **CSS `mask-image` with `data:` SVG URIs in admin.css** (pseudo-elements on `.addlink`, `.deletelink`, `.messagelist .success`, ...): no markup change for links and flash, small per-page HTML. Rejected: (a) a boolean cell still needs new markup (a class hook and the accessible text), so the "no markup" benefit is partial; (b) older Chrome and Safari need the `-webkit-` prefixed duplicate of every mask (evidence: 2026-10-08-css-mask-image-support); (c) icons for buttons identified only by `name` (`_save`, `_continue`, the search button, the logout button) would need new classes or attribute selectors on `name`, coupling style to form semantics; (d) the stylesheet would gain `url(` with URL-encoded SVG, against the "no URLs in CSS" rule's spirit and harder to review; (e) a host CSP `img-src` without `data:` might block them (unverified, evidence: 2026-10-08-css-mask-image-support); (f) presence of an icon cannot be asserted from the parsed HTML in tests.
- **SVG sprite (`<symbol>` block in `Layout` + `<svg><use href="#i-name"/></svg>`):** smaller per instance on long lists. Rejected for v1 of the feature: one more moving part (per-page sprite, id uniqueness under host pages) for a saving of about 100 bytes per icon, which HTTP compression largely removes (unverified for the host's server setup).
- **Q9 placement: let `FormPage` pick `BooleanMark` before calling `DisplayValue`:** keeps forms free of the icon import, but splits "how a stored value is shown read-only" between two components, and the mask precedence would have to be repeated in `FormPage`. Rejected; `DisplayValue` remains the single read-only renderer.
- **Unicode / emoji glyphs:** no new markup, but rendering depends on installed fonts (emoji style and color vary by platform; `currentColor` does not apply to color emoji) (unverified). Rejected for the colored boolean and flash icons.
- **Icon font or icon CDN:** forbidden by §11.

## Rationale
- Inline SVG is plain JSX: Hono renders `svg`/`path` without `raw()` and the typings accept the attributes (evidence: 2026-10-08-hono-jsx-inline-svg), so the "no `raw()` / `dangerouslySetInnerHTML`" rule (decision 004) still holds. Path strings are module constants and `name` is a closed union passed only as literals by views, so no request, config or DB value reaches the SVG (XSS).
- Biome's recommended `noSvgWithoutTitle` rule exempts SVGs marked `aria-hidden="true"` (evidence: 2026-10-08-biome-no-svg-without-title), which matches the decorative-icon requirement without `<title>` text that would otherwise have to live in `messages.ts`.
- `stroke="currentColor"` makes icons follow the text color in both color schemes. The two new colors reach at least 4.7:1 on every listed background in light and dark mode, above the 3:1 WCAG non-text contrast threshold (evidence: 2026-10-08-icon-color-contrast).
- The visually hidden text uses existing `messages.yes` / `messages.no`, so no UI string leaves `messages.ts` and no message key is added.
- Icons are inline (1em) next to existing text, so the 767px layout is unchanged; no JavaScript is involved.
- The CSS gain is about a dozen short rules; the SVG presentation attributes are inline so an icon still renders at 16px with stroke-only shapes if the stylesheet fails to load.

## Consequences
- New file `src/views/icons.tsx`. Changed: `src/views/{layout,dashboard,list,form,delete,confirm-action}.tsx`, `src/views/format.ts` (`cellBoolean`), `src/routes/list.ts` (sets `Cell.bool`), `src/forms/widgets.tsx` (`DisplayValue` booleans, Q9), `src/static/admin-css.ts` (icon rules, two custom properties per scheme; `ADMIN_CSS_VERSION` changes automatically).
- The text content of a boolean list cell changes from `✓` / `✗` to `messages.yes` / `messages.no`; `test/list.test.ts` "shows booleans as check marks" is updated accordingly. The same holds for read-only boolean form fields; the `DisplayValue` boolean case in `test/widgets.test.ts` changes from `✓` to `messages.yes`. All other existing tests pass unchanged.
- The action `run` button, the login button, paginator links, filter links, breadcrumb links and cell links get no icon (confirmed by the user, Q10).
- There is no `info` flash level (`FlashLevel` is `success | warning | error`); no level is added (confirmed by the user, Q8).
- views.md (Icons section, selectors, `Cell`, `format.ts`, `FormPage`, CSS requirements), forms.md (`DisplayValue`), support.md (messages rule note), routes-handlers.md (List step 4b), test-strategy.md, README.md (source layout, index).
